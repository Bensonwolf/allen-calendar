# Allen Calendar（DayFlow）

個人行事曆與待辦事項管理網頁。每天早上打開，就能看到今天的行程、待辦、完成進度與最重要的一件事。

單人、本機使用：不需要登入、不需要後端，所有資料存在瀏覽器的 LocalStorage。

## 安裝與啟動

需要 Node.js 18 以上（開發時使用 Node 20）。

```bash
npm install
```

```bash
npm run dev
```

啟動後打開終端機顯示的網址（預設 <http://localhost:5173>）。

其他指令：

| 指令 | 用途 |
| --- | --- |
| `npm run build` | 型別檢查並產生正式版到 `dist/` |
| `npm run preview` | 在本機預覽 `dist/` 的正式版 |
| `npm test` | 執行自動化測試（Vitest） |
| `npm run typecheck` | 只做 TypeScript 型別檢查 |

## 部署到 GitHub Pages

專案已附上 GitHub Actions 流程（`.github/workflows/deploy.yml`）：每次推送到 `main` 分支，會自動執行測試、打包並部署。

1. 在 GitHub 建立一個新的儲存庫（不要勾選自動建立 README）。
2. 到儲存庫的 **Settings → Pages**，把 **Source** 設為 **GitHub Actions**。
3. 推送程式碼到 `main` 分支，等 **Actions** 分頁的流程跑完。
4. 網址為 `https://你的帳號.github.io/儲存庫名稱/`。

`vite.config.ts` 中的 `base: './'` 讓打包後的檔案使用相對路徑，因此不論儲存庫叫什麼名字都不需要再改設定。

注意：部署後每位訪客的資料都只存在他自己的瀏覽器，彼此看不到對方的任務與行程。

## 主要功能

**今日總覽**
- 依時段顯示早安／午安／晚安、完整日期與星期、今日提示
- 今日進度：任務總數、尚未完成、已完成、完成率與進度條；沒有任務時顯示空狀態（不會出現 NaN）
- 今日焦點：自動挑出今天優先級最高的未完成任務
- 「要做」與「已完成」兩區；勾選立即切換，已完成區可收合並顯示完成時間
- 今日行程（依時間排序，進行中的行程有標記）、未來 7 天的任務與行程
- 逾期提醒區

**行事曆**
- 月／週／日檢視，可切換月份、回到今天、用日期選擇器跳到任一天
- 月檢視每格顯示行程與任務，超過時顯示「+N 更多」；點日期在側邊顯示當天完整內容
- 點日期後按「新增行程」，或雙擊日期直接新增；週／日檢視點時間格新增
- 行程支援全天、跨日、分類顏色與自訂顏色、地點、備註
- 有日期的任務會同步顯示在行事曆上，完成後顯示勾選與刪除線（任務只有一份資料，不會複製）
- 手機上月檢視自動改為圓點的精簡模式

**待辦事項**
- 快速新增（只打名稱按 Enter）與詳細新增（描述、日期、時間、優先級、分類）
- 篩選：全部、今天、明天、未來 7 天、已逾期、已完成；可再依分類、優先級篩選
- 排序：優先級、截止日期、建立時間
- 逾期任務顯示標籤，不會自動刪除或自動完成

**其他**
- 全域搜尋（任務名稱／描述、行程名稱／備註／地點）
- 快捷鍵：`N` 新增任務、`Ctrl/Cmd + K` 搜尋、`Esc` 關閉視窗（輸入文字時不會誤觸）
- 分類管理：新增、改名、改顏色、刪除（刪除時底下的任務與行程移到「其他」）
- 設定：淺色／深色、預設行事曆檢視、每週起始日、是否顯示已完成任務
- 資料：匯出 JSON、匯入 JSON（先驗證格式，不合格不會動到現有資料）、清除所有資料（兩次確認）
- 所有新增、修改、刪除、完成操作都有 Toast 回饋；刪除前有確認視窗
- 響應式：桌面為左側 Sidebar（可收合），手機為底部導覽列與浮動新增按鈕

## 專案架構

```
src/
├─ types.ts                 資料模型：Task、CalendarEvent、Category、UserSettings、AppData
├─ lib/                     不依賴 React 的純邏輯（都有測試）
│  ├─ date.ts               日期工具：DateKey 轉換、月曆格子、顯示格式
│  ├─ tasks.ts              任務篩選、排序、逾期判斷、完成率、狀態切換
│  ├─ events.ts             行程驗證、跨日判斷、週/日檢視排版
│  ├─ storage.ts            DataRepository 介面、LocalStorage 實作、資料驗證、匯出匯入
│  ├─ search.ts             全域搜尋
│  └─ defaults.ts           預設分類、預設設定、ID 產生
├─ store/
│  ├─ appStore.ts           資料 store：Task / Event / Category CRUD，每次變動立即存檔
│  ├─ uiStore.ts            介面狀態：視窗、Toast、行事曆選取日期
│  └─ index.ts              組合 store 與 Repository（更換資料庫只需改這裡）
├─ hooks/                   useNow、useShortcuts、useActions
├─ components/              layout / ui / tasks / events / calendar / SearchDialog
└─ pages/                   Dashboard、CalendarPage、TasksPage、CompletedPage、SettingsPage
```

### 更換資料庫

畫面與 store 只依賴 `DataRepository` 介面（`load` / `save` / `clear`）。要換成 Supabase 或其他後端時，實作同一個介面，再到 `src/store/index.ts` 把 `LocalStorageRepository` 換掉即可。目前介面是同步的；遠端資料庫需要改成非同步，並在 store 加上載入中狀態。

## 設計決定

以下是需求沒有明確指定、由我選擇的做法：

- **日期儲存格式**：任務與行程的日期存成 `yyyy-MM-dd`、時間存成 `HH:mm` 的本地字串，不經過 UTC，所以不會因時區換算跑到前一天或後一天。只有 `createdAt`／`updatedAt`／`completedAt` 這類「發生瞬間」用 ISO UTC 時間戳記。
- **時區**：以裝置的系統時區為準。在台灣使用即為 Asia/Taipei；沒有另外做時區設定。
- **今日任務的定義**：截止日是今天的任務，加上「今天完成」的任務（例如今天補完的逾期任務）。完成率以此計算。
- **逾期**：有時間的任務過了該時間算逾期；只有日期的任務要等當天結束才算。今天以前到期的未完成任務出現在首頁的逾期提醒區。
- **行事曆元件**：自行以 date-fns 實作月／週／日檢視，沒有採用 FullCalendar，目的是讓任務與行程用同一套樣式呈現並控制打包大小。
- **路由**：使用 HashRouter（網址帶 `#/`），讓打包後的檔案放在任何靜態主機或子路徑都能運作。
- **「其他」分類**：是刪除分類時的歸屬處，可以改名與改顏色，但不能刪除。
- **「顯示已完成任務」設定**：影響行事曆與待辦清單；今日總覽與「已完成」頁面一律顯示。
- **資料損壞**：LocalStorage 內容無法解析時，原始內容會另存到 `allen-calendar:corrupt-backup`，再以空白資料啟動並提示。
- **多分頁**：在另一個分頁修改資料後，其他分頁會自動同步。

## 尚未實作與已知限制

- 資料只存在這個瀏覽器的 LocalStorage：換瀏覽器、換裝置或清除瀏覽器資料就看不到，請定期用「匯出資料」備份。容量上限約 5 MB，一般個人使用足夠。
- 沒有重複行程／重複任務（每週固定的課、每天的例行事項需要逐筆建立）。
- 沒有提醒通知（瀏覽器通知、Email）。
- 行事曆不支援拖曳移動或拉長行程，需開啟編輯視窗修改。
- 月檢視中，跨日行程會在每一天各顯示一個標籤，不是一條連續的橫條。
- 週／日檢視中，任務統一顯示在上方的「全天」列，不會依截止時間放進時間格。
- 沒有時區設定，一律使用裝置時區。
- 刪除沒有復原（Undo），刪除前會先確認。
- 元件與版面的測試是手動在瀏覽器進行的，沒有自動化的元件測試或端對端測試。
